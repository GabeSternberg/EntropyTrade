# Deployment implementation review

The primary agent independently inspected the private-access, runtime, backup, collector
export and research-validation implementations supplied by the handoff contributors, then
reviewed the complete resulting diff. Review used source inspection and actual kernel,
GnuPG, HTTP, SQL and browser execution; no Windows access was inferred.

Concrete issues corrected before acceptance:

- Generated WorkingDirectory used ExecStart quoting, which systemd treated as a literal
  leading quote and rejected. It now uses the path directive grammar; real
  `systemd-analyze --user verify` passes. ExecStart/list paths retain their own escaping.
- Backup maintenance now runs the crypto/lease contexts in its own process so interruption
  cleans private plaintext before restarting only the previously active research unit.
- Startup rejects untracked application/deployment source and shared/symlinked environment
  directories, while allowing uv's normal interpreter leaf symlink.
- Dataset recovery requires the actual versioned schema for every committed dataset;
  synthetic fixtures were corrected instead of adding a production fixture exception.
- Every frozen model and portable descriptor must agree with the experiment's file hash,
  including when an attacker rewrites checksums.json. Dormant/unpromoted artifacts are
  validated without reading feature/target values or loading joblib.
- A real GnuPG test shifted time two days beyond controlled key expiry and demonstrated
  that old authenticated ciphertext was incorrectly refused. Expiry/revocation still blocks
  new encryption; historical decryption accepts these advisory statuses only after complete
  authenticated GPG success and an independently trusted ciphertext hash. Cipher integrity,
  wrong keys, output budgets and fatal statuses still refuse.
- Public-only validation/encryption disables GPG agent autostart; an invalid secret-key
  recipient cannot leave an unnecessary encryption-home agent running.
- A new snapshot inventory preflight retained explicit symlink refusal wording for existing
  operator/tests; no rejection was relaxed.
- The older E browser harness now selects F's explicit readiness tab and its renamed
  Evidence & audit tab, with a bounded action timeout. The initial timeout and explicitly
  interrupted stale-label attempt are retained. These are harness navigation updates;
  application code and CI-executed tests remain the tested source commit.

The first complete CI run (`44169131925`, application `1372619`) passed 2,119 tests
and exposed two further recovery cases. Requirement identities generated by the existing
planner append `-sN` for multi-source policies; recovery now checks that exact convention,
and a new negative case refuses a changed source policy under its old identity. A synthetic
C fixture had persisted its helper's hypothesis-link annotation inside the frozen feature
manifest; it now registers the actual frozen fields and separate links, matching production.
The manifest equality guard remains strict and a new negative test verifies it. Both original
failures and all 56 research/orchestration cases pass locally after these changes. The full
CI log is retained under failed-attempts; it is not represented as a passing run.

The read-only collector export uses one existing O_RDONLY shared-lock descriptor through
complete verification, copying and final pin checks. It never invokes collector run,
initialization, repair, activation or its mutating lock helper. Restores are new inactive
inspection directories outside data/cache. Existing collector compatibility is preserved;
no physical collector evidence has been opened.

The private deployment boundary trusts Windows Tailscale Serve and other local host
software. Controlled loopback header/session tests are not real TLS, Tailscale ACL, device,
WSL namespace, Task Scheduler or reboot acceptance. Native browser sessions exercised local
HTTP mode; Secure cookies in private mode were checked at the actual HTTP handler boundary.
The runbook requires trusted physical HTTPS and allowed/denied identities before deployment.

No empirical edge, authentic strategy eligibility, paid-provider verification, offsite copy,
Windows installation or live-money readiness follows from these controlled software tests.
